Description:

Title

Capstone Prototype Development & Industry Handoff Using Justinmind

Description

In this capstone activity, students will work in groups of a maximum of three members to design and develop a complete web or mobile application prototype using Justinmind by integrating all the UI/UX concepts learned throughout the course. The prototype should include multiple interactive screens, responsive layouts, navigation, form validation, and user-friendly interfaces. Students must create a realistic prototype, test its functionality, prepare developer handoff documentation, and present their work professionally. Finally, each group must submit a comprehensive report in PDF format along with the exported Justinmind prototype.

Learning Objectives

After completing this activity, students will be able to:

Integrate UI/UX design principles into a complete application prototype.

Develop interactive and responsive prototypes using Justinmind.

Apply usability, navigation, and form validation concepts.

Prepare professional developer handoff documentation.

Present and document a complete UI/UX project.

Software Required

Justinmind Prototyping Tool

MS Word / Google Docs

PDF Converter

Activity Type

Group Activity (Maximum 3 Students per Group)

Activity Instructions

Step 1: Select a Project

Each group should select one application idea such as:

Online Shopping Application

Food Delivery Application

Hospital Management System

Student Management System

Banking Application

Travel Booking Application

Library Management System

Event Management System

Fitness Tracking Application

Online Learning Platform

Step 2: Plan the Prototype

Prepare a simple project plan including:

Application name

Project objective

Target users

Main features

User flow

Screen navigation structure

Step 3: Design the Complete Prototype

Create a complete interactive prototype in Justinmind.

The prototype should include at least:

Splash Screen

Login/Register Screen

Home Screen

Menu/Dashboard

Functional Pages

Search Screen (if applicable)

Profile Screen

Settings Screen

Confirmation or Success Screen

Minimum 8–10 interactive screens should be developed.

Step 4: Add Interactive Features

Implement prototype interactions such as:

Navigation between screens

Buttons and menus

Form validation

Success and error messages

Pop-up dialogs

Interactive menus

Responsive layouts for different devices

Step 5: Test the Prototype

Verify that:

All navigation links work correctly.

Buttons perform the intended actions.

Forms display proper validation messages.

User flow is smooth and error-free.

Responsive layouts function properly on different screen sizes.

Fix any identified issues before submission.

Step 6: Export the Prototype

Export the Justinmind prototype and prepare it for demonstration and developer handoff.

Step 7: Capture Screenshots

Include screenshots of:

Splash Screen

Login/Register Screen

Home Screen

Feature Screens

Responsive Mobile View

Tablet View

Desktop View

Interactive Prototype

Final Prototype Overview

Step 8: Prepare the Report

The report should include:

Cover Page

Group Members' Names and Enrollment Numbers

Subject Name and Code

Project Title

Aim and Objectives

Software Used

Application Description

User Flow Diagram

Screen Descriptions

Prototype Features

Screenshots of All Screens

Prototype Testing Results

Developer Handoff Summary

Challenges Faced

Learning Outcomes

Conclusion

Submission Guidelines

Each group must submit:

One PDF Report

Exported Justinmind Prototype File

Screenshots of all screens

Presentation (if instructed by the faculty)

Submit all files before the deadline.

File Naming Format

Report: GroupNo_BETCE15324_CapstonePrototype.pdf

Prototype: GroupNo_BETCE15324_Prototype

Example:

Group05_BETCE15324_CapstonePrototype.pdf

Group05_BETCE15324_Prototype

Important Instructions

This is a group activity with a maximum of 3 students per group.

Each group must select a unique project topic. Duplicate project ideas, layouts, or reports are not permitted.

The complete prototype, report, screenshots, and documentation must be created by the group members.

Copying work from classmates, previous batches, or internet sources is strictly prohibited.

All content in the report should be written in your own words.

Reports or prototypes containing copied or duplicate content will be treated as plagiarism and may receive zero marks.

Every group member must actively contribute to planning, designing, testing, documentation, and presentation.
